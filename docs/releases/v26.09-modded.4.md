# 26.09-modded.4 - Signal safety and order editing

This Windows x64 release includes the latest master fixes, following `26.09-modded.3`. The previous .3 release and tag remain available as a checkpoint. It includes automatic cargo/passenger/mail transfers, shared lines, timetables and native visual orders from the consolidated modded edition.

## Changes since modded.3

- **Reservations through stations:** a station without a departure signal no longer ends Path/Chain protection. Incoming trains must protect the required continuation to a safe boundary; already-platformed trains recheck before leaving loading, timetable or rule waits. Required waypoint directions remain respected.
- **Conflicting trains and whole-train clearance:** ordinary and standalone Chain signals retain native block admission; Path and combined signals retain path reservations. Entered sections cannot yield to a competing train. Occupation checks include stationary/detached wagons, partial overlaps and conflicting curves/switches. Protection stays until the tail clears.
- **Priorities:** Express takes priority over Local among eligible conflicting requests. Equal-class contenders prefer actual waiters, then longest wait, then the shorter remaining track journey; exact ties use a cached simulation draw. Priorities never override physical occupation or committed reservations. Wait age and tie choices survive matching save/reload.
- **Compact signal key:** one colour per type in either direction: Block grey, Path yellow, Chain dark blue and combined orange. Each facing arrow uses its own type. A compact two-row key in the signal menu uses the native window text colour. Arrow hues identify types, not permission to proceed.
- **Drag orders into and out of blocks:** stop/waypoint captions, consecutive selections and whole sections support validated drops in vehicle Route and shared-line Orders. Use the upper half of a closing arm to append inside, its lower half to drop outside, or the top edge of a header to insert before it. Nested outside drops use the enclosing block. Empty containers are removed; header drags retain nested sections without carrying their parent. Invalid/stale/outside-window drops cancel without mutation.
- **Conditional orders:** the palette includes **Jump if**, with a stable stop/waypoint destination and a normal fall-through when false. Checks include load percentage, vehicle age, aggregate reliability, maximum speed and Always, alongside existing cargo, destination, platform, timetable and year checks. Blocks run independently for each vehicle on a shared line and retain bounded execution.

## Included modded features

Create normal private routes or shared lines across trains, road vehicles/trams, ships and aircraft. Automatic destination-aware cargo transfers need no dedicated Transfer order: coal mine -> truck -> combined road/rail station -> train -> power plant works through ordinary routes. Passenger/mail journeys can use feeders at both ends and share stations with several destinations. Ordinary stations without nearby industry can act as interchanges. Feeder profit uses virtual credit; company payment occurs once at final delivery.

Cargo tabs keep compact expandable destination summaries. Options -> Miscellaneous -> Cargo transfers selects Automatic or Classic. Timetables, automatic spacing, native inline Rules editing, live Path/All route previews and existing gameplay options remain included. Original stops/waypoints retain their native presentation.

This is an independent fork of [OpenLoco](https://github.com/OpenLoco/OpenLoco), built on its [26.09 baseline `e71abfb3`](https://github.com/OpenLoco/OpenLoco/commit/e71abfb3). Upstream supplies the reimplemented Locomotion engine; the features above are this fork's additions and follow-ups. This is not an upstream merge or a claim to include every newer upstream change.

## Download and setup

Download **`OpenLoco-v26.09-modded.4-windows-x64.zip`** and its **`.zip.sha256`** checksum. Extract into a separate folder and run `OpenLoco.exe`. Select your original Chris Sawyer's Locomotion installation, or use:

```text
OpenLoco.exe --locomotion_path "C:\Path\To\Locomotion"
```

The ZIP includes the x64 Release executable, project languages, CMake-fetched OpenGraphics objects, release/setup notes and project notices. Original Locomotion DAT/G1/music files, player saves/profiles, debug symbols and test executables are excluded. Original game assets are required. Linux/macOS users can build from source; no verified binaries for those platforms are attached.

## Save compatibility

Packed SV5/SC5 structures remain unchanged. Keep each save and its matching **`.olines` v5**, **`.osignals` v4**, **`.orules` v1** (including optional PHASES data) and **`.ocargodist` v1** companions together.

Signals v4 preserves waiting priority and committed protection, validates the matching native save/train identities, and reads signal companions v1-v3. The .3 executable cannot read v4 signal companions or newly used Rules condition values: use separate backed-up saves when returning to .3. Never replace your only checkpoint save. Missing CargoDist companions migrate existing quantities; malformed/mismatched companions produce named warnings instead of attaching incorrect data.

No save-container conversion, consists/coupling/shunting, text language, mod loader, NSF/NOF, multiplayer or raised map/object limits is added.
