# Decisions

| ID | Date | Decision | Why | Consequence |
| --- | --- | --- | --- | --- |
| D1 | 2026-10-10 | Three layers: engine, `src/Modding`, packages under `mods/`. | Gameplay hardcoded in the exe cannot be installed separately. | Mods do not link into `OpenLoco.exe` as features. |
| D2 | 2026-10-10 | Do not implement NSF or NOF in this change. | Upstream has named both and has not published a spec or code. The v26.01 post says old formats stay supported. | Extended state waits. SV5 import stays exact. |
| D3 | 2026-10-10 | New saves will be a versioned chunk container, not a sidecar. | Sidecars split from the save and desync. | Container design must be able to wrap upstream NSF later. |
| D4 | 2026-10-10 | `.olmod` is a proposed zip with `manifest.json`. | No official mod package exists. | Revisit if upstream defines one. Directory loader ships first. |
| D5 | 2026-10-10 | No native DLL mods by default. | Untrusted code would have full process rights. | Scripts, when chosen, are sandboxed. |
| D6 | 2026-10-10 | Script language is not chosen. | Lua, Wasm, and a custom logic graph have different costs. See below. | Closed by D26. The player uses blocks on the order list. |
| D7 | 2026-10-10 | One logic runtime for lines, yards, and shunters. | Separate languages would drift. | Railway-only actions are capability-gated, not a second interpreter. |
| D8 | 2026-10-10 | API compatibility is same major.minor and running patch >= required patch. | `0.x` minor breaks would be hidden by a looser rule. | Bump minor when the manifest or loader behaviour breaks. |
| D9 | 2026-10-10 | Unknown manifest keys are ignored; nested objects are rejected. | Forward field adds should not break the loader. Arbitrary JSON should not become a hidden API. | Schema growth is explicit. |
| D10 | 2026-10-10 | Hybrid monorepo. | One repo keeps engine and mods in sync while the API moves quickly. Separate repos are better once packages are stable. | Gameplay mods may move out later. Examples stay here. |
| D11 | 2026-10-10 | Classic cargo and passengers stay the default. | The original game must remain playable. | Destination systems are mods or options. |
| D12 | 2026-10-10 | Shunting uses real movement and reservations. | Teleporting wagons would not match the request and would break signals. | Shunting cannot start until consists and reservations exist. |
| D13 | 2026-10-10 | Do not change map or object constants yet. | They are packed into the save. | `ENGINE_LIMITS.md` is descriptive. |
| D14 | 2026-10-10 | Do not activate every installed mod automatically. | A dropped folder must not change a game session. | Superseded in part by D15. The refusal to auto-run unlisted mods still stands. |
| D15 | 2026-10-10 | Activate only ids listed in `<mods>/enabled.json`. The `mods` command does this and exits. A normal launch does it for `%APPDATA%\OpenLoco\mods` only when that directory already exists. | Players need a path that loads a data mod without recompiling, and a missing folder must leave vanilla startup alone. | The first action is `log` only. No simulation mutation and no save write. |
| D16 | 2026-10-10 | The mod manager edits `enabled.json` only. A toggle applies on the next launch, not to the running session. | Enablement is an install switch, not save data. Reloading mods mid-session would run `log` actions again and is not defined for future gameplay mods. | The window does not write SV5 files. |
| D17 | 2026-10-10 | Install copies an unpacked directory and does not enable it. Remove deletes only that mod directory after disabling it. Symbolic links are refused. Upgrade replaces a folder only when it already contains the same mod id. | A copy must not activate itself, escape the mods folder, or delete an unrelated directory. | Zip packages remain a later decision. A failed upgrade removes the staging copy and, if the old folder was already deleted, can leave the mod missing. |
| D18 | 2026-10-10 | The mod manager Install button uses the Windows folder dialog. `.olmod` zip packages stay unimplemented because libzip is not linked by CMake. | The existing save browser only selects files. | Players install an unpacked mod folder. A zip format waits until an archive library is already part of the build. |
| D19 | 2026-10-10 | No obsolescence, infinite money, and calendar speed are engine options in `openloco.yml`, shown on Options > Miscellaneous. They are not separate mods. | A data mod can only log a line. These rules have to run inside the simulation. Native DLL mods stay rejected. | The options do not change the SV5 layout. Disable vehicle breakdowns was already on that tab and was left in place. |
| D20 | 2026-10-10 | Path, one-way path, and chain signal types and pending reservations are stored in `<save>.SV5.osignals`, like the lines companion. Track a train stands on is rebuilt from its routing ring after load. | Every bit of the SV5 signal element is used, and the user chose a companion over building the save container first. | Older builds and vanilla see block signals. Renaming a save outside the game loses the signal types. Supersedes D3 for this feature until the container exists. |
| D21 | 2026-10-10 | Path and chain are flags on a normal signal. One-way and two-way stay the existing direction buttons. Companion files are version 2, and version 1 kinds still load. The train window can show one train's reserved path. | The signal choices have to combine, and the reserved path has to be visible on the map. | A version 1 one-way path becomes a path flag on the sides that were built. The back of a single-sided signal is blocked. |
| D22 | 2026-10-10 | Plain block signals keep OpenLoco's own look. Path, chain, and combined posts use that same look: green while clear, red when the head passes, yellow on the signals behind that red, green again when the tail leaves. Reservation does not paint the post. Route-indicator lights stay vanilla. Companion version 3; version 2 loads clear stale route lights. | Claim colours left path and chain posts red until a train approached, then yellow, while the block signals beside them stayed green. | Block signals still turn red before trains reach them, as in OpenLoco. Saves from version 2 builds lose route-indicator housings on special signals until a train passes the junction again. |
| D23 | 2026-10-11 | The mod loader, title-screen Mods window, `mods` command, and Hello World sample are removed. | Shared lines, timetables, and path and chain signals are edited in the game. The loader only logged a sample line. | D1, D4, and D8 through D18 described that loader. They are not a reason to add it back. |
| D24 | 2026-10-11 | A line can paint vehicles with its main colours or with one of ten special schemes, the same types as the company colour tab. Bit 0 is steam through bit 9 ships. A vehicle marked Own keeps the paint-tool colours. Companion files are version 5. Versions 1 to 4 still load with the schemes off and the scheme colours equal to the line colours. | Line paint, company colours, and the vehicle paint brush have to apply at the same time, including one train in its own colours. | Company special schemes use bit 1 for steam. Line schemes use bit 0. An older companion has no Own list, so every assigned vehicle follows the line when Paint is on. |
| D25 | 2026-10-12 | Release `v26.09-modded.1` is the checkpoint before block rules. | The next work changes orders for vehicles and shared lines. That release stays the build to return to. | Do not rewrite that tag. Block-rule work starts after it. |
| D26 | 2026-10-12 | Player rules are MakeCode-style blocks on the order list, in one Rules window, for a vehicle and for a shared line. A group of stops and waypoints can share one block. The order byte has no room for a new type. | Supersedes the open choice in D6. One runtime, as in D7, runs these blocks. Yard and cargo blocks join this palette later. The spec is `docs/mods/PROGRAMMABLE_LOGIC.md`. |
| D27 | 2026-10-12 | Native block rules use stable order keys, independent vehicle runtime, and a v1 `.orules` companion. | D28 | 2026-10-12 | Rail platform checks read physical occupation of connected station track pieces, including wagons, excluding the evaluating vehicle. | Timetable data alone does not describe physical occupation. | Reservations alone are ignored; this check does not force platform selection. |

## Script language tradeoffs

Not selected.

| Option | Advantage | Cost |
| --- | --- | --- |
| Lua | Small, known, easy to embed. | Must remove `io`, `os`, `package`, and `debug`. Determinism needs a banned or fixed math story. |
| WebAssembly | Stronger sandbox, language choice for authors. | Heavier toolchain, harder for players to edit, time and memory limits need a runtime. |
| Instruction graph plus text view | Matches the visual editor, easy to bound and save, deterministic. | Not a general programming language. External authors cannot reuse an ecosystem. |

D26 closes this choice. The player drags blocks. There is no text view to keep in step with a second language.

## Release artifacts

Engine builds stay the OpenLoco executable plus its open data. Native features ship in that build; no `.olmod` loader is shipped. Original DAT, G1, and music files are excluded. OpenGraphics objects already fetched by CMake are a separate upstream asset pack and are not part of a mod.
